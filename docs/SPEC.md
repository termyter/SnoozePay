## 1. Общее описание проекта

### 1.1. Концепция
Мобильное приложение-будильник для iOS и Android с уникальной механикой: при нажатии кнопки «Отложить» с баланса пользователя списывается денежная сумма. Базовую сумму штрафа пользователь выбирает сам (от 10 до 1000 рублей). Доступна прогрессивная шкала, при которой каждое последующее откладывание стоит дороже. Если баланс равен нулю, откладывание заблокировано — пользователь вынужден встать и выключить будильник.

**Цель приложения** — помочь людям бороться с привычкой бесконечно откладывать будильник, используя финансовый стимул.

### 1.2. Целевая аудитория
- Люди, которые систематически откладывают будильник и опаздывают
- Возраст: 18–45 лет (основная группа)
- Студенты, офисные работники, фрилансеры
- Люди, мотивированные на самодисциплину и продуктивность
- Пользователи, готовые использовать финансовую мотивацию для изменения привычек

### 1.3. Проблема
Стандартные будильники позволяют бесконечно откладывать сигнал без каких-либо последствий. Это приводит к опозданиям, нарушению режима сна и снижению продуктивности. Существующие решения (задачки для выключения, QR-коды) работают на выключение, но не на откладывание. Финансовый штраф создаёт реальные последствия за каждое откладывание.

### 1.4. Монетизация (куда уходят штрафы)
- **MVP (первый этап):** средства поступают разработчику
- **Второй этап (будущее):** возможность переводить штрафы на благотворительность

### 1.5. Платформы и технологии

| Параметр | MVP (v1.0) | Версия 2.0 |
|----------|------------|------------|
| **iOS** | Swift, UIKit, AlarmKit (iOS 26+) / Local Notifications (iOS 18+), StoreKit 2, UserDefaults | + Backend sync, CloudKit |
| **Android** | Kotlin, Jetpack Compose, AlarmManager, Google Play Billing, SharedPreferences | + Backend sync |
| **Backend** | ❌ Нет (offline-first) | ✅ Node.js/Python + PostgreSQL |
| **Минимальная iOS** | iOS 18 (Local Notifications), iOS 26 (AlarmKit — полноценный будильник) | iOS 18+ |
| **Минимальная Android** | Android 8.0 (API 26) | Android 8.0+ |
| **Архитектура** | MVVM, Offline-first | MVVM + Cloud sync |
| **Дизайн** | Минималистичный, тёмная/светлая тема | + Виджеты, расширенная статистика |

## 2. Функциональные требования

### 2.1. Управление будильниками

#### 2.1.1. Создание будильника
- Выбор времени (часы, минуты) — через picker (scroll wheel)
- Повтор по дням недели: Пн, Вт, Ср, Чт, Пт, Сб, Вс (множественный выбор)
- Название будильника (текстовое поле, например: «Работа», «Спортзал», «Учёба»)
- Выбор звука будильника (из предустановленных бесплатных звуков)
- Включение/выключение вибрации
- Настройка времени откладывания (по умолчанию 9 минут, диапазон: 1–30 минут)
- Настройка базовой суммы штрафа за откладывание (от 10 до 1000 рублей)
- Включение/выключение прогрессивной шкалы штрафов

#### 2.1.2. Список будильников
- Отображение всех будильников в виде списка
- Каждый будильник показывает: время, дни повтора, название, сумму штрафа, статус (вкл/выкл)
- Toggle-переключатель для включения/выключения каждого будильника
- Свайп для удаления будильника
- Нажатие на будильник открывает экран редактирования

#### 2.1.3. Редактирование будильника
Все параметры из создания доступны для редактирования. Изменения применяются после нажатия «Сохранить».

#### 2.1.4. Глобальные настройки откладывания
- Возможность задать время откладывания для всех будильников разом
- Возможность переопределить для каждого будильника индивидуально

### 2.2. Экран сработавшего будильника

#### 2.2.1. Основной экран
- Полноэкранный интерфейс (поверх Lock Screen, если возможно)
- Отображение текущего времени крупным шрифтом
- Название будильника
- Две кнопки:
  - **«Выключить»** — бесплатно, полностью останавливает будильник
  - **«Отложить (X ₽)»** — платно, показывает сумму, которая будет списана
- На кнопке «Отложить» отображается сумма: «Отложить (50 ₽)»
- Звук и вибрация продолжаются до нажатия одной из кнопок

#### 2.2.2. Логика кнопки «Отложить»
1. Пользователь нажимает «Отложить»
2. Система проверяет **локальный баланс** (UserDefaults/SharedPreferences)
3. Если баланс >= суммы штрафа:
   - Списание записывается локально
   - Будильник откладывается на заданное время
4. Если баланс < суммы штрафа:
   - Кнопка «Отложить» неактивна (серая)
   - Отображается: «Недостаточно средств — пора вставать!»
5. Через заданное время будильник звонит снова

**⚠️ Важно:** Списание происходит **мгновенно** и **локально**. Нет зависимости от интернета.

#### 2.2.3. Прогрессивная шкала штрафов
Если пользователь включил прогрессивную шкалу для будильника:

| Откладывание | Множитель | Пример (база 50 ₽) |
|--------------|-----------|---------------------|
| 1-е          | x1        | 50 ₽                |
| 2-е          | x2        | 100 ₽               |
| 3-е          | x4        | 200 ₽               |
| 4-е          | x8        | 400 ₽               |
| 5-е          | x16       | 800 ₽               |

Шкала сбрасывается при каждом новом срабатывании будильника (на следующий день).

#### 2.2.4. Логика кнопки «Выключить»
В MVP: простое нажатие кнопки выключает будильник. Бесплатно, без дополнительных условий.

**Будущее развитие (V2):** добавление заданий для выключения (решить задачку, сфотографировать QR-код).

### 2.3. Баланс и платежи

#### 2.3.1. Внутренний баланс (MVP — локальное хранение)
- У каждого пользователя есть внутренний баланс в рублях
- Баланс отображается на главном экране приложения
- **Баланс хранится локально:**
  - **iOS:** UserDefaults (`balance` key, Double)
  - **Android:** SharedPreferences (`user_balance`, Float)
- При откладывании сумма списывается из локального баланса
- **Нет синхронизации между устройствами** в MVP (фича для V2)

#### 2.3.2. Пополнение баланса (через IAP)
Пополнение реализуется через **Consumable In-App Purchase** (расходуемые покупки):

**iOS (StoreKit 2):**
- Пользователь покупает пакеты баланса
- Варианты: 49 ₽, 149 ₽, 299 ₽, 499 ₽, 999 ₽
- После успешной покупки: баланс увеличивается в UserDefaults
- StoreKit 2 автоматически защищает от дублирования транзакций
- **Нет backend верификации в MVP** — полагаемся на StoreKit 2

**Android (Google Play Billing):**
- Аналогично через Billing Library 5+
- Consumable products
- После acknowledge() — баланс увеличивается в SharedPreferences

**Комиссия сторов:** 15% (для разработчиков < $1M/год) или 30%

#### 2.3.3. История транзакций (локальная)
- **iOS:** Core Data или SQLite
- **Android:** Room database
- Таблица transactions:
  - `id` (UUID)
  - `type` (topup / charge)
  - `amount` (Double/Float)
  - `alarm_id` (String, опционально)
  - `created_at` (Date/Timestamp)
- Список всех списаний/пополнений доступен в настройках

### 2.4. Статистика и мотивация

#### 2.4.1. Экран статистики (MVP)
- Общая сумма потраченная на откладывание (за неделю, месяц, всё время)
- Количество откладываний за период
- Среднее количество откладываний за утро
- Визуальная диаграмма расходов (простая столбчатая)
- Мотивационные сообщения: «На этой неделе вы потратили 350 ₽. Это 2 чашки кофе!»

**Источник данных:** локальная база транзакций.

#### 2.4.2. Серии без откладывания
- Счётчик дней подряд без откладываний (streak)
- Лучший streak за всё время
- Простое поздравление при достижении 7, 14, 30 дней

### 2.5. Звуки будильника
- Набор из 8–12 предустановленных бесплатных звуков (royalty-free)
- **iOS:** `.caf` или `.aiff` файлы в bundle (до 30 секунд для уведомлений)
- **Android:** MP3/OGG файлы в `res/raw/`
- Предпрослушивание звука при выборе
- **Будущее (V2):** загрузка собственных звуков

## 3. Техническая архитектура (MVP — Offline-first)

### 3.1. Обзор архитектуры MVP

| Компонент | Технологии | Ответственность |
|-----------|------------|-----------------|
| **iOS-клиент** | Swift, UIKit, StoreKit 2, AlarmKit / UNUserNotificationCenter | UI, логика будильника, IAP, локальное хранение |
| **Android-клиент** | Kotlin, Jetpack Compose, Google Play Billing, AlarmManager | UI, логика будильника, IAP, локальное хранение |
| **Backend** | ❌ Нет в MVP | — |
| **Хранилище** | UserDefaults/SharedPreferences + Core Data/Room | Баланс, будильники, транзакции |

**Принцип:** приложение полностью автономно. Работает без интернета.

### 3.2. Надёжность будильника (критический раздел)

#### 3.2.1. iOS — ограничения и решения

**Проблемы:**
- Local Notifications ограничены 30 секундами звука
- Нельзя переопределить беззвучный режим и «Не беспокоить»
- Приложение не просыпается при фоновом уведомлении без действия пользователя

**Решение — двойная стратегия:**

**Стратегия A (iOS 26+, AlarmKit) — приоритетная:**
- AlarmKit позволяет создавать полноценные системные будильники
- Работает на уровне системы, как Clock.app
- Поддержка: полноэкранный экран на Lock Screen, Dynamic Island, Apple Watch
- Звонит даже в беззвучном режиме
- **Минимальная версия:** iOS 26

**Стратегия B (iOS 18–25, Local Notifications) — фолбэк:**
- `UNUserNotificationCenter` с Time Sensitive флагом
- Планирование серии уведомлений
- Действия в уведомлении: «Выключить» и «Отложить (X ₽)»
- **Ограничения:** может не сработать в беззвучном режиме

**Рекомендация:** в маркетинге указать iOS 26+ для полноценной работы.

#### 3.2.2. Android — реализация
- `AlarmManager` с EXACT алармами (`setExactAndAllowWhileIdle`)
- Foreground Service для воспроизведения звука
- Full-screen Intent для экрана будильника поверх Lock Screen
- Запрос разрешения `SCHEDULE_EXACT_ALARM` (Android 12+)
- Battery optimization whitelist

**На Android ограничения менее жёсткие — будильник работает надёжно.**

### 3.3. Локальное хранилище (MVP)

#### 3.3.1. iOS (UserDefaults + Core Data)

**UserDefaults:**
```swift
// Хранение баланса
UserDefaults.standard.set(500.0, forKey: "user_balance")
let balance = UserDefaults.standard.double(forKey: "user_balance")
```

**Core Data (транзакции):**
- Entity `Transaction`:
  - `id: UUID`
  - `type: String` (topup / charge)
  - `amount: Double`
  - `alarmID: String?`
  - `createdAt: Date`

**Core Data (будильники):**
- Entity `Alarm`:
  - `id: UUID`
  - `time: Date`
  - `repeatDays: [Int]` (0=Пн, 6=Вс)
  - `name: String`
  - `soundID: String`
  - `vibrationEnabled: Bool`
  - `snoozeMinutes: Int`
  - `penaltyAmount: Double`
  - `progressiveScale: Bool`
  - `enabled: Bool`

#### 3.3.2. Android (SharedPreferences + Room)

**SharedPreferences:**
```kotlin
// Хранение баланса
sharedPreferences.edit().putFloat("user_balance", 500f).apply()
val balance = sharedPreferences.getFloat("user_balance", 0f)
```

**Room Database (транзакции и будильники):**
```kotlin
@Entity
data class Transaction(
    @PrimaryKey val id: String = UUID.randomUUID().toString(),
    val type: String, // "topup" | "charge"
    val amount: Float,
    val alarmId: String?,
    val createdAt: Long
)

@Entity
data class Alarm(
    @PrimaryKey val id: String = UUID.randomUUID().toString(),
    val time: Long, // millis since epoch
    val repeatDays: List<Int>,
    val name: String,
    val soundId: String,
    val vibrationEnabled: Boolean,
    val snoozeMinutes: Int,
    val penaltyAmount: Float,
    val progressiveScale: Boolean,
    val enabled: Boolean
)
```

### 3.4. Логика списания (offline)

Списание штрафа происходит **локально** без зависимости от сервера:

1. Будильник звонит, пользователь нажимает «Отложить»
2. Приложение проверяет локальный баланс
3. Если баланс >= штрафа:
   - Списание баланса: `balance -= penaltyAmount`
   - Сохранение в UserDefaults/SharedPreferences
   - Запись транзакции в Core Data/Room
   - Будильник откладывается
4. Если баланс < штрафа:
   - Кнопка «Отложить» неактивна

**Нет интернета — нет проблем.** Будильник работает полностью автономно.

## 5. Бизнес-модель

### 5.1. Модель монетизации

| Источник дохода | Описание | Этап |
|-----------------|----------|------|
| Штрафы за откладывание | Основной доход. Средства с баланса пользователей (за вычетом комиссий сторов) | MVP |
| Благотворительность | Опция перечисления штрафов на благотворительность (мотивация для пользователей) | V2 |
| Премиум-функции | Расширенная статистика, кастомные звуки, задания для выключения | V3 (опционально) |

### 5.2. Экономика

Приложение **бесплатное** для скачивания. Доход формируется только от штрафов за откладывание.

**Пример расчёта (для 1000 активных пользователей):**
- Среднее пополнение: 200 ₽/месяц на пользователя
- Валовый доход: 200 000 ₽/месяц
- Комиссия стора (15%): -30 000 ₽
- **Серверные расходы:** 0 ₽ (нет backend в MVP)
- **Чистый доход:** ~170 000 ₽/месяц

**Примечание:** это оптимистичный сценарий. Реальные цифры зависят от retention и среднего чека.

- Согласие на списание средств — при первом использовании функции откладывания
- Все документы должны быть доступны внутри приложения и по ссылке (для модерации)

### 6.2. Ключевые юридические положения
- Чёткое описание: деньги списываются при нажатии кнопки «Отложить»
- Пользователь самостоятельно пополняет баланс и осознаёт, что средства списываются безвозвратно
- Разработчик не несёт ответственности за опоздания из-за технических сбоев
- Disclaimer о том, что будильник на iOS < 26 может не сработать в беззвучном режиме

### 6.3. Возврат средств
- Стандартный возврат через App Store / Google Play (по правилам сторов)
- В пользовательском соглашении: штрафы являются добровольными и не подлежат возврату
- **Механизм подтверждения (опционально):** краткий таймер (3 секунды) перед списанием

### 6.4. Правила App Store и Google Play
- Штрафы реализуются как расходование внутреннего баланса (пополняется через IAP) — это легитимная модель
- Не является азартными играми (нет случайного результата)
- Не является подпиской (разовые пополнения)
- Необходимо пройти ревью и возможно дать пояснения модераторам
